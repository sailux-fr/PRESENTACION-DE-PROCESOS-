¿Qué es un proceso?

Un proceso es un programa que se encuentra actualmente en ejecución dentro del sistema operativo, pasando de ser un archivo estático a una entidad dinámica y activa. Representa la unidad fundamental de trabajo en un sistema operativo moderno, siendo la abstracción principal sobre la que el SO gestiona la ejecución de tareas. Es una entidad activa que posee recursos asignados por el sistema operativo, incluyendo tiempo de CPU, memoria, archivos abiertos y dispositivos de E/S.

Programa vs Proceso

Un PROGRAMA es un archivo pasivo almacenado en disco. Es simplemente un conjunto de instrucciones escrito en código que permanece estático hasta que es invocado para ejecutarse.

  • ARCHIVO EN DISCO

    • No consume CPU ni memoria de forma activa

  • ENTIDAD PASIVA

    • Permanece inalterado hasta su ejecución.

  • CÓDIGO ESTÁTICO

    • Conjunto fijo de instrucciones compiladas.

Un PROCESO es una entidad activa que reside en memoria y compite por el uso del procesador (CPU). Tiene un estado dinámico que cambia conforme avanza su ciclo de vida.

  • RESIDE EN MEMORIA

    • Ocupa espacio en RAM durante su ejecución.

  • COMPITE POR CPU

    • El sistema operativo arbitra el acceso al procesador.

  • ENTIDAD DINÁMICA

    • Cambia de estado a lo largo de su ciclo de vida.

Ciclo de Vida del Proceso

Los procesos transitan entre estados bien definidos durante su existencia en el sistema operativo. Cada transición está controlada por eventos del sistema o decisiones del planificador.

Bloque de Control de Proceso

El PCB identifica y describe a cada proceso dentro del sistema operativo.

  • PID

    • (Process ID): número único que el SO asigna a cada proceso para identificarlo de forma inequívoca en el sistema

  • ESTADO Y REGISTROS

    • Estado actual del proceso (New, Ready, Running, Waiting, Terminated) y el valor de los registros del CPU para restaurar el contexto al retomar ejecución.

  • PRIORIDAD Y MEMORIA

    • Prioridades de planificación y los límites de memoria asignada: direcciones base y límite del espacio de direcciones del proceso

El PCB permite al SO guardar y restaurar el contexto completo durante un cambio de contexto.

Sin el PCB, el sistema operativo no podría gestionar la multitarea ni retomar procesos interrumpidos de forma correcta.

Planificación del Procesador

Administra el tiempo de CPU entre los procesos que compiten por su uso.

OBJETIVOS:

  • MAXIMIZAR EL RENDIMIENTO

    • Mantener el procesador ocupado la mayor parte del tiempo posible para maximizar el rendimiento del sistema.

  • EQUIDAD Y JUSTICIA

    • Garantizar que cada proceso reciba una porción justa del tiempo de CPU y evitar la inanición (starvation) de procesos de baja prioridad.

  • MINIMIZAR TIEMPOS DE RESPUESTA

    • Reducir el tiempo de espera y de respuesta para mejorar la experiencia del usuario y la eficiencia del sistema operativo.

NIVELES DE PLANIFICACIÓN

  • LARGO PLAZO

    • Controla la admisión de procesos al sistema

    Decide qué procesos del conjunto de trabajos pasan a la memoria principal para ser ejecutados

    También regula el grado de multiprogramación

  • MEDIANO PLAZO

    • Se encarga del intercambio de procesos entre la memoria principal y el disco

    Puede extraer procesos de la memoria para liberar recursos y volver a introducirlos cuando sea conveniente.

  • CORTO PLAZO

    • Es el planificador que trabaja con mayor frecuencia

    Selecciona el siguiente proceso de la cola de listos para asignarle la CPU

ALGORITMOS DE PLANIFICACIÓN DE CPU

ALGORITMOS NO APROPIATIVOS:

  • FCFS — First-Come, First-Served

    • Los procesos son atendidos en el orden en que llegan, son sencillo de implementar; generando un efecto convoy cuando un proceso largo bloquea a los demás.

  • SJF — Shortest Job First

    • Primero se ejecuta el proceso que tiene el menor tiempo de ráfaga de CPU, minimizando el tiempo promedio de espera, teniendo conocimiento previo de cada duracion de cada proceso

ALGORITMOS APROPIATIVOS:

  • Round Robin

    • Asigna a cada proceso un Quantum, es decir, una unidad de tiempo fija de CPU, de manera cíclica; garantizando equidad para sistemas de tiempo compartido

  • Planificación por Prioridades

    • Cada proceso tiene una prioridad asignada y la CPU se otorga al proceso con mayor prioridad; puede ser apropiativa o no apropiativa, dependiendo de la implementación.
